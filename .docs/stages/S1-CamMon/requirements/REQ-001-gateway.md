## 背景与目标

为摄像机提供设备隔离、约束文件操作及缓存透明读取，减少远程存储小写入。

## 当前口径

1. Samba 4.25.0，host 网络；独立账号、独立共享，虚拟索引由 Unix socket 提供。发现默认 auto：UDP 137/138 可用时启动 nmbd，任一不可用时沿用 NAS 发现；external 显式共存，internal 强制自带发现。TCP 139/445 仍须独占。
2. 目录最多两层，MP4 名称和时间严格验证；相机 X 为数字字符串。随机写、追加、头部修改、合法改名均支持。
3. 同 X 时间更晚的后续片段触发 10 秒静默封存，无后续时 30 分钟；均须关闭全部写入句柄。
4. 真实存储支持本地磁盘、SMB2/3 和 NFS，默认选择本地磁盘，容器路径默认 `/data`；Compose 将 NAS 的 `/volume1/WebCam` 绑定挂载到 `/data`，宿主机目录可通过 `CAMMON_STORAGE_PATH` 修改。SMB2/3 使用 smbprotocol，NFSv3/v4.0 使用 libnfs CFFI，全程用户态。整文件临时转存、刷新、大小/SHA256 校验、原子改名后释放缓存。
5. 已封存录像只读；离线继续使用可用缓存；不足返回 ENOSPC；恢复上传、索引和任务。

## 功能拆解 / 实施拆解

1. native/vfs_cammon.c、native/register_module.py：固定 ABI 构建与索引 VFS。
2. cammon/core.py、rpc.py、database.py：文件身份、句柄租约、状态机及恢复。
3. cammon/storage.py、nfs_build.py、samba.py：后端和设备认证发现。

## 验收标准

1. 真实 SMB1 客户端认证、隔离、目录深度、命名、写入、合法改名、转存后读取及只读保护。
2. 多个 X、迟到旧片段、写入收尾及 30 分钟规则独立正确。
3. 本地磁盘、SMB 与 NFS 临时半文件转存、故障/ENOSPC 注入、校验、当前进程保留源文件并重试且计数一次；2026-10-09 用户明确允许重启丢失临时录像。
4. 正式部署前摄像机实机认证及文件操作联调。
5. UDP 137、138 单独或同时被占用时，auto / external 模式继续提供 TCP 139/445 上的 SMB1；已有 NAS NetBIOS 发现不受影响。internal 保留 UDP 冲突报错，所有模式保留 TCP 冲突报错。

### 2026-10-12 NAS NetBIOS 共存验收

- 时间：2026-10-12。
- 场景：目标 NAS 的 UDP 137/138 无法释放，用户要求与已有 NetBIOS 服务共存。
- 操作步骤：本机运行真实 Samba 4.25.0 / VFS，分别占用 UDP 137、138、两者，同时测试显式 external 和空闲端口上的 auto / internal；再启动名称为 NAS-EXISTING 的宿主机 nmbd，启动 CamMon 并查询发现、检查健康、通过 TCP 139/445 登录和随机写读。检查 internal 的 UDP 冲突和各模式 TCP 冲突，以及部署预检退出码。
- 预期结果：共存模式不争抢 UDP，已有服务继续响应；SMB1 和健康检查正常；必须独占的端口仍能报告冲突。
- 实际结果：15 项本机 SMB 协议测试通过，其中 10 项新增共存及启动场景；56 项非集成回归、Ruff、前端生产构建、1 项浏览器流程、三个模式的独立 Compose 解析及锁文件校验通过。云端 amd64 / arm64 各通过全部 92 项容器测试，生产构建、Public 及匿名双架构清单校验通过；目标 NAS 更新后验收待执行。
- 证据：[SMB 集成测试](../../../../tests/test_smb_integration.py)、[Samba 管理](../../../../cammon/samba.py)、[部署预检](../../../../scripts/check_deployment.py)、[成功的 0.1.5 发布运行](https://github.com/hsyhhssyy/CamMon/actions/runs/38253526834)。

### 2026-10-12 NAS 启动与协议现场检查

- 时间：2026-10-12。
- 场景：用户完成 NAS 更新后，请求确认服务和 NetBIOS 共存状态。
- 操作步骤：访问管理页、前端 JS/CSS、/healthz 和未登录的 /api/auth/me；通过真实 SMB 客户端分别连接 TCP 139/445 并强制协商 SMB1；查询 NAS 的 NetBIOS 节点名称。
- 预期结果：页面资源与健康接口正常，external 模式生效；两个端口接受 SMB1，原有 NAS 名称服务仍响应；管理接口保持认证要求。
- 实际结果：页面及资源、健康接口均 HTTP 200，ok=true、protocol_error=null、discovery.mode=external；TCP 139/445 均可连接并成功协商 SMB1；NAS 原有 SMB 服务器名称仍由 NetBIOS 返回。未登录管理接口返回 HTTP 401。未取得设备凭据，因此没有执行 NAS 上的认证、文件写读或后端转存，摄像机实机验收仍待完成。
- 证据：目标 NAS HTTP / SMB / NetBIOS 实际响应；协议探测使用 [impacket 客户端的测试用法](../../../../tests/test_smb_integration.py)。
